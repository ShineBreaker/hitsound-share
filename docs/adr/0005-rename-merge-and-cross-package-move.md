# 改名撞名并包与跨包移动

packages.name 不设唯一约束（不同上传者重名合法存在），但同一上传者的重名包会造成树上歧义。改名撞上已有同名 visible 包时返回 409，前端确认后带 `merge=true` 重发：被改名的包整体并入最老的同名包（`ORDER BY created_at, id` 保证任何客户端选出同一目标），被改名包行删除；文件行 id 不变，组装面板与波形引用不受影响。并包只允许并入自己的包（管理员豁免），与附加上传口径一致。去重沿用影子包合并的三重判等（同 folder_path + 同 name + 同 blob_hash），且去重 EXISTS 必须排除行自身（`t.id <> files.id`）——跨包移动打破了「源包 ≠ 目标包」的隐含前提，不排除时已在目标位的文件会命中自身被静默删除。排除后，被去重行必有同 hash 孪生行存活于目标包，构造上不可能出现归零 blob，所以并包与移动只需 `settleAll` 对齐引用计数、不跑 RECLAIM 与 R2 blob 删除，仅补删被并包的 legacy original.zip（v4 前历史包残留，purge-zips 只清点现存包行够不到它）。

移动走 `POST /api/files/move`（文件 ids / 小类前缀两种模式）：源侧权限与删除文件一致（文件级 owner，非管理员时所有被移文件须本人上传），目标包须自己的包（管理员豁免）。小类级联迁移用 substr 全值前缀比较而不用 LIKE（folder_path 含 `#` 空格 `&` 逗号是常态，通配符转义易错；substr 按字符计，与 D1 的 UTF-8 TEXT 自洽），`toFolder=''`（目标包根）时必须 CASE 特判剥掉前导 `/`，去重与迁移两处的路径映射表达式逐字一致。撞名判定按字节序即大小写敏感，与既有查询行为一致，是有意口径。
