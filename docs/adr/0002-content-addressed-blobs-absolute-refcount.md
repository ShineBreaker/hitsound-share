# 内容寻址 blob + 引用计数绝对对齐

音效在各个包之间大量重复，所以 R2 只按 sha256 存一份 blob（key 由 `blobKey()` 组装），靠 `blobs.refcount` 管理生命周期。引用计数一律**对齐**：用集合式 SQL 重算为「全部 visible 包的实际引用数」，不做 +1/-1 累加。累加在 D1 批次中途失败或重放时会产生永久偏差，而对齐是幂等的，重跑一次就能自愈历史错账。代价是每次对齐要扫较多行（done 为全表），用行写量换子请求预算和正确性。

## Consequences

- 回收条件是「引用计数 ≤ 0 且没有任何音效文件引用」：pending 包预先登记的 blob 行受外键保护，不会被误删。
- 所有账本写操作必须是与包大小无关的常数次子请求（集合式 SQL、`DELETE … RETURNING`、R2 批量删除），不得逐 hash 循环。
