# done 核验只覆盖新 blob

原先的 done 通过分页 list 整个 `blobs/` 前缀来比对大小，成本随全站存量线性增长（8GB 水位约 4 万对象、约 40 页），迟早越过 50 子请求上限。现在的做法是：引用计数 > 0 的 blob 已经被核验过，只比对声明大小与账本大小，不访问 R2；只有新 blob（引用计数 ≤ 0）走 `verifyFreshBlobs`。新 blob 不超过 24 个时逐个 ranged GET，一次拿到对象大小和魔数，全量覆盖；超过 24 个时，涉及的前缀不超过 16 个就逐个 list 这些前缀，否则 list 全量，魔数只抽查 16 个。

## Consequences

- 上传大量新 blob（前缀覆盖面很广）且全站存量又很大时，全量 list 仍然可能越界。彻底解决需要把 done 改成可续传的分段核验（要新增核验进度列、做 schema 变更），目前没有做。
- 已提交 blob 的内容可信度依赖首次核验，R2 端对象被带外篡改不在防御范围内。
